# GPS Link 제작 일지 — 2026년 10월 15일

- 작성 기준: 대한민국 시간(Asia/Seoul)
- 프로젝트: GPS Link — GPS 위치 수신·공유·지도 관제 웹사이트
- GitHub: https://github.com/unogim4/lte-gps-map
- 운영 사이트: https://lte-gps-map.vercel.app/
- 관리자 지도: https://lte-gps-map.vercel.app/admin.html

## 1. 오늘의 제작 목표

GPS 장치가 LTE로 위도·경도를 전송하면 웹 지도에 표시하고, 다른 컴퓨터나 휴대폰에서도 HTTPS로 접속해 최신 위치를 확인하는 웹사이트를 만든다.

제작 중 다음 요구를 추가 반영했다.

- URL 좌표 입력으로 위치 표시
- 접속한 컴퓨터·휴대폰의 현재 위치 표시
- 방문자가 동의한 경우에만 관리자에게 위치 공유
- TM800 펌웨어의 고정 수신 경로 지원
- 약 5초 간격의 위치 갱신과 지도 따라가기
- GitHub 수정 후 Vercel 자동 배포

## 2. 구성과 데이터 흐름

### 기술 구성

| 영역 | 구현 |
|---|---|
| 화면 | HTML, CSS, JavaScript; PC·모바일 대응 |
| 지도 조작 | Leaflet 1.9.4 |
| 지도 이미지 | OpenStreetMap 타일 |
| 웹 호스팅·HTTPS | Vercel |
| 서버 API | Vercel Node.js Functions |
| 위치 저장소 | Upstash Redis Free |
| 소스 관리·배포 | GitHub main → Vercel Production 자동 배포 |

### 하드웨어 GPS

```text
GPS 모듈 → TM800/마이크로컨트롤러 → LTE 모뎀
→ HTTPS 수신 API → Redis 최신 좌표 저장
→ 장치 지도에서 약 5초마다 조회·표시
```

### 휴대폰 방문자 위치 공유

```text
방문자가 공유 안내 확인·동의 → 실시간 공유 시작
→ 브라우저 위치 권한 허용 → 약 5초마다 서버 전송
→ 같은 방문자 기록 갱신 → 관리자 지도에서 약 5초마다 조회
```

일반 접속으로 자신의 위치를 화면에 표시하는 동작과, 관리자에게 위치를 전송하는 동작은 별개다. 위치 권한 허용만으로 관리자에게 자동 전송하지 않는다.

## 3. 제작 및 개선 과정

### 초기 지도 사이트 구현

- `?lat=...&lng=...` URL을 열면 해당 좌표에 마커를 표시하도록 구현했다.
- 위도·경도 직접 입력과 위치 URL 복사 기능을 추가했다.
- 위도 -90~90, 경도 -180~180의 범위를 검증했다.
- PC에서는 정보 패널과 지도를 나란히, 모바일에서는 지도를 위쪽에 표시했다.

### Vercel 배포와 GitHub 연결

- 초기 Vercel 연결 도구에서는 팀 접근 권한 오류(403)가 발생했다.
- 브라우저에서 Vercel에 로그인한 뒤 소스를 직접 업로드해 첫 운영 배포를 완료했다.
- GitHub `unogim4/lte-gps-map` 저장소에 소스를 업로드했다.
- 이후 Vercel에 GitHub 저장소를 연결했다.
- `main`에 문서 수정 커밋을 올려 자동 Production 배포가 실행되는 것을 확인했다.
- 운영 주소는 `https://lte-gps-map.vercel.app/`로 유지했다.

### Redis 연결

- Vercel Marketplace에서 Upstash Redis Free를 생성했다.
- 생성 당시 무료 플랜 화면에는 월 500,000 명령이 표시되었다. 실제 사용 한도와 요금 정책은 공급자 설정을 기준으로 확인한다.
- Redis는 Vercel Production 환경에만 연결했다.
- Vercel이 제공하는 `KV_REST_API_URL`, `KV_REST_API_TOKEN` 이름을 지원하도록 API를 보완했다.
- 기존 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`도 계속 지원한다.
- GPS 장치 전송용 인증키를 서버 비밀값으로 설정했다.
- 서버 메모리를 임시 저장소로 쓰지 않고 Redis에 저장해 다른 기기에서도 같은 위치를 조회하게 했다.

### 접속 기기의 현재 위치 표시

- 기본 주소로 접속하면 브라우저 Geolocation API를 호출하도록 변경했다.
- 사용자가 위치 권한을 허용하면 현재 위치와 추정 정확도를 표시한다.
- 위치 권한 거부·위치 확인 실패·시간 초과에 대한 안내를 추가했다.
- ‘내 위치 찾기’ 버튼으로 다시 시도할 수 있게 했다.
- 명시적인 좌표 URL이나 장치 ID URL은 해당 모드를 유지한다.
- GPS가 없는 컴퓨터는 Wi-Fi·네트워크 등을 통한 추정 위치가 표시될 수 있다.

### 지도 403 오류 수정

- OpenStreetMap 타일에 `403 Access blocked`가 표시되는 문제를 확인했다.
- 기존 `Referrer-Policy: no-referrer` 설정이 지도 서버의 Referer 요구와 충돌하는 것을 확인했다.
- `strict-origin-when-cross-origin`으로 변경해 사이트 출처를 전송하되, 외부에 전체 경로나 쿼리가 전달되지 않게 했다.
- 지도 타일 주소를 공식 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`로 통일했다.
- 브라우저에서 지도 이미지가 정상 표시되는 것을 확인했다.

참고 정책: https://operations.osmfoundation.org/policies/tiles/

### 로그인 요구와 모바일 빈 지도 개선

- 사진의 브랜치 배포 주소에서 Vercel 로그인을 요구하는 것을 확인했다.
- 사용자 승인 후 이 프로젝트의 Vercel Authentication을 해제했다.
- 운영 주소와 브랜치 주소에 비로그인 요청이 HTTP 200으로 응답하는 것을 확인했다.
- 모바일 빈 지도에 대응해 Leaflet JS·CSS·이미지·라이선스를 사이트 안에 포함시켰다.
- 모바일 지도 컨테이너에 명시적 높이를 적용했다.
- ResizeObserver와 지도 크기 재계산 처리를 추가했다.
- 지도 로딩 실패 안내를 위치 수신 상태와 분리했다.
- 아이폰 크기(393×852)의 브라우저 화면에서 지도·마커와 타일 로딩을 확인했다.
- 실제 아이폰 Safari·카카오톡 등 모든 브라우저를 실기로 검증한 것은 아니다.

### 동의 기반 방문자 위치 공유와 관리자 지도

- 방문자에게 공유 목적·전송 항목·보관기간을 안내하는 화면을 추가했다.
- 동의 체크와 공유 시작 조작 없이 위치를 전송하지 않게 했다.
- 초기 1회 공유 기능에서, 최종적으로 동의 기반 실시간 공유 기능으로 확장했다.
- 관리자 전용 위치 조회 API와 관리자 지도를 구현했다.
- 관리자 인증키는 GPS 장치 전송키와 분리했다.
- 공유 세션별 인증값을 사용해 같은 방문자의 위치를 갱신하고 삭제할 수 있게 했다.
- 마지막 전송 위치는 Redis TTL로 최대 24시간 보관한다.
- 관리자 지도는 최근 위치 최대 200건을 표시한다.
- 관리자 인증키는 URL이나 브라우저 영구 저장소에 저장하지 않고 페이지 메모리에서 사용한다.
- 공개 장치 위치 API와 방문자 위치 저장 네임스페이스를 분리했다.

### TM800 고정 경로 지원

- 전달받은 설명에서 TM800 시험 펌웨어가 도메인 뒤에 `/radlot/data`를 붙이는 구조를 확인했다. 실제 펌웨어 소스나 패킷은 전달받지 못했다.
- `/radlot/data` 및 `/radlot/data/`를 수신 API로 연결했다.
- JSON POST, 폼 POST, GET 쿼리의 십진수 위도·경도를 지원했다.
- `lat`/`latitude`, `lng`/`lon`/`longitude` 필드를 정규화했다.
- GPS 전송키 인증과 Redis 저장은 기존 기능을 재사용했다.
- 원시 NMEA·바이너리·알 수 없는 패킷을 임의로 해석하지 않도록 했다.
- 좌표 없는 GET은 수신 규격을 안내하며, 저장 성공과 구별했다.
- 클라이언트용 단계별 Markdown 안내서와 상대방 Codex용 작업 지시서를 작성했다.

### 5초 실시간 갱신과 지도 따라가기

- 휴대폰은 동의 후 화면이 활성화된 동안 약 5초마다 현재 위치를 획득·전송한다.
- 최초 POST로 공유 기록을 만들고, 이후 PUT으로 같은 기록의 최신 좌표를 갱신한다.
- 5초마다 새 방문자가 생성되지 않도록 했다.
- 실시간 공유 중지, 동의 해제, 화면 비활성화 시 추가 전송을 중지한다.
- 관리자 지도 조회 주기를 약 5초로 변경했다.
- 관리자 지도에 위치 따라가기 켜기·끄기 기능을 추가했다.
- TM800 장치 지도는 약 5초마다 최신 위치를 조회한다. 실제 장치 전송 주기는 펌웨어에서 별도로 설정해야 한다.
- 실시간 갱신 요청이 계속될 때 속도 제한 카운터가 영구 누적되지 않도록 제한 키의 만료 처리도 보완했다.

## 4. 최종 API 및 접속 주소

| 용도 | 경로 / 주소 | 인증 |
|---|---|---|
| 기본 지도·내 위치·방문자 공유 | `https://lte-gps-map.vercel.app/` | 접속 로그인 없음; 위치 권한·공유 동의 별도 |
| 좌표 URL | `/?lat=37.5665&lng=126.9780` | 없음 |
| TM800 지도 | `/?device=tm800-01` | 공개 장치 조회 |
| GPS 좌표 저장·조회 | `/api/location` | 저장 시 GPS 전송키 필요 |
| TM800 호환 수신 경로 | `/radlot/data` | 좌표 저장 시 GPS 전송키 필요 |
| 관리자 지도 | `/admin.html` | 관리자 인증키 필요 |
| 방문자 공유 생성 | `POST /api/visitors` | 명시적 공유 동의 필요 |
| 방문자 위치 갱신 | `PUT /api/visitors` | 공유 세션 인증값·동의 필요 |
| 방문자 위치 목록 | `GET /api/visitors` | 관리자 Bearer 인증 필요 |
| 방문자 공유 삭제 | `DELETE /api/visitors` | 해당 공유 세션 인증값 필요 |

### TM800 요청 예시

```http
POST /radlot/data HTTP/1.1
Host: lte-gps-map.vercel.app
Content-Type: application/json
X-GPS-Key: YOUR_GPS_WRITE_KEY

{"device":"tm800-01","lat":35.214388,"lng":129.098566}
```

위 값은 형식 설명용 예시이며 실제 장치 위치를 뜻하지 않는다. `YOUR_GPS_WRITE_KEY`는 운영자가 별도로 제공하는 실제 GPS 전송키로 바꾼다. 관리자 인증키를 대신 사용하지 않는다.

펌웨어가 경로를 자동으로 붙인다면 설정 도메인은 다음과 같다.

```text
https://lte-gps-map.vercel.app
```

주소에 `#` 또는 `/#`를 넣지 않는다. `#` 뒤의 데이터는 서버로 전송되지 않는다.

## 6. 현재 한계와 후속 작업

1. **실제 TM800 펌웨어 호환성 미검증**
   - 소스, 보드·모뎀 모델, 실제 HTTP 패킷을 확보해야 한다.
   - 실제 GPS·LTE 장비에서 이동·재연결·인증·TLS 검증이 필요하다.

2. **장치 전송 주기는 장치에서 설정**
   - 웹사이트가 TM800의 GPS를 직접 읽을 수는 없다.
   - 펌웨어가 약 5초마다 새로운 좌표를 서버로 보내도록 구현해야 한다.

3. **브라우저 백그라운드 추적 미지원**
   - 휴대폰 화면 잠금·앱 전환·페이지 종료 시 공유를 중지한다.
   - 지속적인 백그라운드 추적은 별도의 앱 또는 전용 하드웨어 구성이 필요하다.

4. **정확히 5초의 지연 없는 실시간을 보장하지 않음**
   - 폴링 방식이며 GPS 획득, LTE·Wi-Fi, 서버 응답 지연에 따라 간격이 늘어날 수 있다.
   - 장치 송신 주기와 지도 조회 주기 때문에 표시 지연이 추가될 수 있다.

5. **최신 위치 중심**
   - 하드웨어 GPS는 장치별 최신 한 건을 저장한다.
   - 이동 경로 이력, 지오펜스, 알림 기능은 아직 없다.

6. **운영 사용량과 접근 범위**
   - 5초 주기 지속 사용 시 Redis 명령량과 서버 요청량을 확인해야 한다.
   - 공개 장치 지도는 장치 ID를 알면 조회할 수 있다. 방문자 공유 위치는 관리자 인증으로 보호한다.
   - 위치 데이터는 실제 사람의 신원이나 센서의 진위를 증명하지 않는다.

## 8. 비밀정보 관리

GPS 전송키·관리자 인증키·Redis 토큰의 실제 값은 이 문서와 GitHub에 포함하지 않았다. 해당 값은 서버 비밀 환경변수와 운영자에게 별도로 전달한 키 파일로 관리한다.

문서에 있는 키 이름과 자리표시자는 실제 인증키가 아니다. 장치 개발 담당자에게는 GPS 전송키만 별도의 비공개 방식으로 전달하며, 관리자 인증키는 운영자용으로 보관한다.
