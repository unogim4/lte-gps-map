# 다른 컴퓨터에서 GPS Link 작업 이어가기

작성: 2026-10-21 (Asia/Seoul)

## 1. 저장소 받기

다른 컴퓨터에 Git과 Node.js 22 이상을 준비한 뒤, 원하는 작업 폴더에서 실행합니다.

```sh
git clone https://github.com/unogim4/lte-gps-map.git
cd lte-gps-map
npm test
```

이 프로젝트는 정적 HTML/CSS/JavaScript와 Node.js Vercel Functions로 구성됩니다. 현재 package.json에는 별도 설치 의존성이 없으므로 단위 테스트에 npm install이 필요하지 않습니다. Node 내장 테스트 러너를 사용하며, 작성 시점 테스트는 20개입니다.

이미 저장소를 받은 컴퓨터에서는 변경 파일이 있는지 먼저 확인하고 원격 변경을 받습니다.

```sh
git status
git pull --ff-only
```

로컬 변경과 충돌하면 변경 내용을 보존한 채 해결하세요. 강제 초기화하지 마세요.

## 2. Codex 앱에서 열기

다른 컴퓨터의 Codex 앱에서 방금 받은 `lte-gps-map` 폴더를 프로젝트로 엽니다. GitHub에 수정 사항을 올리려면 해당 컴퓨터에도 GitHub 쓰기 인증이 필요합니다. 기존 연결 방식이나 GitHub CLI/Git 인증을 사용하고 인증 토큰을 소스에 넣지 마세요.

새 채팅에 다음 내용을 넣으면 이전 맥락을 이어받는 데 도움이 됩니다.

```text
이 저장소는 운영 중인 GPS Link 웹사이트다. docs/OTHER_COMPUTER.md, README.md,
docs/dev-log/2026-10-15.md, TM800.md를 읽고 현재 코드를 확인해줘.
운영 주소는 https://lte-gps-map.vercel.app 이고, main에 올리면 Vercel이 자동 배포한다.
브라우저 위치 표시, 동의 기반 휴대폰 5초 공유, 관리자 지도, TM800 /radlot/data
수신 기능이 있다. npm test로 기존 상태를 검증하고 아래 요청을 이어서 작업해줘.
실제 인증키는 저장소에 없으며 공개 코드나 로그에 노출하면 안 된다.

다음에 할 작업: [여기에 원하는 수정 사항 입력]
```

현재 대화의 전체 기록은 저장소 파일에 포함되지 않습니다. 제작 일지와 이 인수인계 문서가 다른 컴퓨터에서 사용할 작업 맥락입니다.

## 3. 현재 서비스와 배포 연결

- GitHub: https://github.com/unogim4/lte-gps-map
- 운영 사이트: https://lte-gps-map.vercel.app/
- 관리자 지도: https://lte-gps-map.vercel.app/admin.html
- TM800 지도: https://lte-gps-map.vercel.app/?device=tm800-01
- Vercel 프로젝트: `lte-gps-map`, 팀 `unogims-projects`
- `main` 커밋 → Vercel Production 자동 빌드·배포

코드·일반 문서 수정은 GitHub를 통해 반영할 수 있습니다. 서버 비밀값 변경이나 재배포 설정 조작은 Vercel 프로젝트에 접근할 수 있는 계정이 필요합니다. 운영 주소는 유지하며 변경합니다.

이 방식은 GitHub를 통해 소스를 동기화하고 각 컴퓨터에서 개발하는 방식입니다. 현재 컴퓨터를 켜 둘 필요는 없지만, 새 컴퓨터에 개발 도구와 필요한 계정 연결을 준비해야 합니다.

## 4. 기능 현황

### 내 위치와 지도

- 기본 홈페이지는 접속 기기의 위치 권한을 요청해 현재 위치를 표시합니다.
- `?lat=...&lng=...`는 지정 좌표, `?device=...`는 서버가 받은 장치 위치를 표시합니다.
- Leaflet 1.9.4는 `public/vendor/leaflet/`에 포함되어 있습니다.
- OpenStreetMap 타일은 공식 URL을 사용합니다.
- Referrer-Policy는 `strict-origin-when-cross-origin`입니다. Referer를 완전히 막으면 지도 타일이 차단될 수 있습니다.
- 모바일 지도 높이와 크기 재계산을 별도로 처리합니다.

### 휴대폰 실시간 공유

- 방문자의 명시적 공유 동의와 시작 버튼 조작 후에만 서버로 전송합니다.
- 화면이 활성화된 동안 약 5초마다 갱신합니다.
- 공유 중지·동의 해제·화면 비활성화 시 중지합니다. 백그라운드 추적은 지원하지 않습니다.
- 최초 POST 이후 세션별 PUT으로 같은 방문자 기록을 갱신합니다.
- 마지막 전송 후 최대 24시간 보관하며 같은 페이지에서 삭제할 수 있습니다.

### 관리자 지도

- `/admin.html`에서 관리자 인증키로 인증합니다.
- 약 5초 간격 조회 및 위치 따라가기 켜기/끄기를 지원합니다.
- 최근 공유 위치 최대 200건을 표시합니다.
- 관리자 인증 없이 방문자 목록을 조회할 수 없습니다.

### 하드웨어 GPS / TM800

- `/api/location` 및 `/radlot/data`로 좌표를 받습니다.
- JSON POST·폼 POST·GET 쿼리를 지원하며, GPS 전송키가 필요합니다.
- 좌표는 WGS84 십진수 도입니다. 원시 NMEA·바이너리 패킷은 임의 해석하지 않습니다.
- 실제 TM800 펌웨어의 패킷·보드·모뎀은 아직 미확인입니다.
- 장치의 실제 전송 주기는 펌웨어에서 5초로 설정해야 합니다.
- 서버는 장치별 최신 위치를 저장하며 이동 경로 이력은 없습니다.

## 6. 인증키와 저장소 설정

운영 서버의 비밀값은 Vercel에 남아 있으므로 컴퓨터를 바꾼다는 이유로 다시 만들 필요가 없습니다. 소스 수정과 단위 테스트는 실제 운영 비밀값 없이 가능합니다.

서버에서 사용하는 환경변수 이름:

- `KV_REST_API_URL` + `KV_REST_API_TOKEN`
- 또는 `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`
- `GPS_WRITE_KEY`: 하드웨어 GPS 전송 인증키
- `ADMIN_ACCESS_KEY`: 관리자 지도 인증키

실제 값은 저장소에 없습니다. 이전 컴퓨터의 `GPS-전송키.txt`와 `관리자-인증키.txt`는 필요한 경우 운영자가 별도의 비공개 수단으로 옮기세요. 파일 이름과 변숫값의 역할을 구분하고, 실제 키를 커밋·문서·스크린샷에 넣지 마세요.

새 컴퓨터에서 관리자 지도를 사용하는 경우 관리자 인증키 파일만 별도로 전달받아 입력하면 됩니다. GPS 장치 시험에는 GPS 전송키를 사용합니다.

## 7. 검증과 후속 작업

- 코드 수정 후 변경 범위에 맞는 검증과 `npm test`를 실행합니다.
- 새 기능의 프런트엔드→API→저장소→지도 동작을 확인합니다.
- 실장비가 없으면 서버 시험과 실제 GPS·LTE 시험 결과를 구분합니다.
- 합성 시험 좌표에는 별도 장치 ID 또는 명확한 테스트 이름을 사용하고, 다른 장치 데이터를 덮어쓰지 않습니다.
- 운영 변경이 main에 반영되면 자동 배포 결과와 기존 운영 주소 동작을 확인합니다.
- 진행 중인 작업을 다른 컴퓨터로 넘길 때는 변경 사항을 커밋·푸시하고, 다음 컴퓨터에서 해당 브랜치를 받습니다.

남은 주요 과제는 TM800 실제 펌웨어 패킷 확보와 GPS·LTE 실기 연동 검증입니다.
